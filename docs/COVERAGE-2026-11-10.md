## What the owner runs

All read-only. Deploy first, so the report is on the server:

    cd /srv/xc-predictor && git pull && systemctl reload xc-predictor

**A. Is the main feed scraped from the server?** Last night's summary line:

    grep -h "scrape_anet" $(ls -d /srv/xc-predictor/logs/nightly_* | tail -3 | sed 's|$|/SUMMARY.txt|')

**B. Coverage before** (before tonight's run picks up the new code). About a page of output per source:

    cd /srv/xc-predictor && set -a && . /etc/xc-predictor.env && set +a && /srv/venv/bin/python scripts/coverage_report.py --show 15 2>&1 | grep -v '^\[' > /tmp/coverage_before.txt; wc -l /tmp/coverage_before.txt; head -250 /tmp/coverage_before.txt

**C. After tonight's run:** the new step's lines and any blocks.

    d=$(ls -d /srv/xc-predictor/logs/nightly_* | tail -1); cat $d/01z_coverage.log; grep -h "polite\|challenge\|blocked" $d/scrape_*.log $d/01_local_*.log | head -20

**D. The women's 7000 m race.** What each feed stored for it:

## What changed in code

- `scripts/coverage_report.py`: sections `meets`, `races`, `rows` and `misreads`, broken down by week and by state, each with the reason a meet is missing. `--nightly` writes `coverage_nightly` and exits 1 when a source's last-14-days coverage fell 5 or more points since the last run, which marks the step FAILED so the owner gets mail.
- `deploy/nightly_update.sh`: one line, `01z_coverage`, after the scrapes. **This is the pipeline chat's file;** that one line is the only change.
- `sources/timers.py` / `sources/land.py`: the `ext_seen` table, rejected pages resting, recent meets re-read fresh.
- `tfrrs/parser/parse_xc_page.py`, `parse_xc.py`: combined-gender races split by each runner's team, and "0:00.0" stored as no time.

Tests: `tests/test_tfrrs_mixed_race.py` (real page, `tests/fixtures/tfrrs/xc_28712_mixed_race.html`), `tests/test_sources_timers.py` (5 new), `tests/test_coverage_report.py`.

## For the data-cleaning chat

Rows already stored that the scraper wrote wrong. The scraper is fixed; these are rows from before the fix.

1. **TFRRS rows with `time_seconds = 0` and no status.** They should be `time_seconds NULL, status 'NT'`. Count: `coverage_report.py --section misreads`, column `time<=0`, tfrrs row.
2. **TFRRS combined-gender divisions.** `meets_tfrrs.division_distances` entries whose `div_name` names both genders (`--section races`, "both-gender races"). Every row in them was normalised under the girls' gender. The clean fix is a re-scrape of those meet ids: the parser now splits them, and a re-scrape rewrites rows and blob together. If a re-scrape is not possible, each row's real gender is its `team_slug` suffix (`_m` / `_f`).
3. **Women's 7000 m (Steve Reeder 2021):** wait for query D. If the source page itself says 7000 for the women, it is a stored-row fix (a distance pin); if not, it is the division-key bug (#6) and I fix the scraper.
4. **Undated meets:** the `misreads` section lists the main feed's undated meets with their rows' own date, which is the date the `meets` row lacks.
