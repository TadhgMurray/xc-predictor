**6. tfrrs and anet meets colliding on one meet_id** — proposal: split meet
pages by div_id (<100 tfrrs, ≥100 anet). Do not code the threshold from
memory; measure it first:

```sql
-- How real is the collision, and does the div_id threshold hold?
SELECT CASE WHEN r.div_id < 100 THEN 'lt100' ELSE 'ge100' END AS bucket,
       count(DISTINCT r.meet_id)                                AS meets,
       count(*)                                                 AS rows,
       count(*) FILTER (WHERE r.person_id IS NULL)              AS tfrrs_like
FROM   results r
GROUP  BY 1;

-- Meets that actually hold both populations (the pages to split):
SELECT r.meet_id,
       count(*) FILTER (WHERE r.div_id < 100)  AS low_div_rows,
       count(*) FILTER (WHERE r.div_id >= 100) AS high_div_rows
FROM   results r
GROUP  BY r.meet_id
HAVING count(*) FILTER (WHERE r.div_id < 100) > 0
   AND count(*) FILTER (WHERE r.div_id >= 100) > 0
ORDER  BY count(*) DESC LIMIT 25;
```

A better discriminator than div_id probably exists — tfrrs rows have
`person_id`-vs-`athlete_id` asymmetries (`panels.py ATHLETE_KEY` note) and
`meets_tfrrs` membership is definitive: `EXISTS (SELECT 1 FROM meets_tfrrs t
WHERE t.meet_id = r.meet_id)`. If the second query returns real collisions,
split the page on the definitive source column, not a numeric guess. TF is
the open question the div_id guess can't answer — same census against
`results_tf` first.

**25 / 30 — NOT WHAT THEY LOOKED LIKE. Investigated, not fixed.**
The rankings API is not missing these filters. `parseFilters` already accepts
`state`, `school`, `grade`, `year`, `course`, `date_from/to`, and the template
already has a **State** control at line 136. So:
- 25 is really "no SCHOOL input in the filter bar" — the API supports it, the
  UI does not expose it. Small, but it is a UI change, not an API one.
- 30 is a **data** problem wearing a UI problem's clothes. `rankings.html:329`
  says outright: *"No nation column exists yet. State is the only geography
  stored."* Yet the athlete page renders `NCAA DI #120 · WEST #68 · PAC-12
  #22`, so that data exists SOMEWHERE (the college list / conference tables)
  and is simply not joined into `ranking_results`. Wiring it is a
  build_ranking_results change plus new filter columns — medium, not quick.

⚠ THE GENERAL LESSON FOR THE REST OF THE WEBSITE LIST: "the filter is
missing" has three possible causes — no UI control, no API parameter, or no
column — and they are hours apart in cost. Check which before promising.
