# Handoff 2026-09-18 — the team-id rekey, and what to run

The owner's call, verbatim: *"Ur gonna do schools by team id. Only,
everywhere ... Issue is ppl going to wrong school ... Anything else left
we'll just let live as separate school text, although we can link across
tfrrs and anet. The state will also be separate, but try to keep consistent
across."* Then: *"No do the team id and such things first, then the crests."*

## Why

`school_identity` infers identity by clustering athletes' home states, and
that inference loses to its own evidence whenever a name is shared. Measured
today with `scripts/team_identity_census.py`:

    Georgetown, team 20898, anet_state DC  --  athlete-modal state ID
    clusters:  Georgetown (TX) 804 primary,  Georgetown (DC) 386

    Wyoming,   team 21595, anet_state WY
    clusters:  Wyoming (MI) 464 primary,  Wyoming (WY) 334

So the university is outranked by a high school of the same name and its
athletes are filed under the wrong school. A team id is anet's own
identifier and `anet_state` is anet's own record of where the team is — a
fact we fetched, not a quantity we computed. Identity goes back to being a
lookup.

**This is additive.** `results.school` stays exactly as scraped. Checked
before starting: `speed_ratings_db` keys ratings on `person_id` and touches
`school` only for club detection, and `engine/college_flag` keys pools on the
school STRING, not on state — so a rekey that adds a `team_id` layer cannot
move ratings or pools. Renaming strings would.

## The census, for reference

    results      40,083,976 rows   89.3% carry a team id   (anet 99.6%, tfrrs 0%)
    results_tf  192,380,748 rows   80.9%                   (anet 97.6%, tfrrs 0%)
    distinct team ids the rows name        68,866
    anet_team has metadata for             48,522
    ... named by rows but NOT fetched      20,344   <- the long pole
    today's identity            64,971 clusters over 54,926 names
    names that never carry a team id      614,844
    people who raced for 2+ team ids    1,176,030

⚠ **That last number is why the owner's athlete rule needed amending.** 1.18M
people raced for two or more teams, and most are real transfers (high school
→ college). "Same athlete ⇒ same school" applied across *different names*
would marry Oregon High School to the University of Oregon. The amended rule,
which the owner agreed to: athlete overlap may **correct the state** of a
name that is already the same name, and may confirm a variant spelling
(`school_name.relation() == "same"`). It must never merge two different
names. `racecast/school_name.py`'s header documents this exact trap.

⚠ **614,844 "names with no team id" is the wrong denominator.** tfrrs names
are mostly one-off spellings and roster statuses on a handful of rows each.
`link_tfrrs_to_anet.py` now prints ROW coverage, which is the figure that
decides how much the unresolved remainder deserves. Read that before
building anything else for it.

## Run order

Phase 0 and 1 are written and pushed. Phase 2's linker already existed; it
gained a coverage report. Phases 3–5 are not written yet.

### Phase 0 — fetch the 20,344 unknown teams  (~11h, metadata only)

Nothing can key on team id while a third of the named teams have no name or
state. No images; `--no-core` is safe because `GetTeamCore` only carries
WebsiteSport/TeamCode/RegionID, which identity does not use.

    cd /srv/xc-predictor && set -a && . /etc/xc-predictor.env && set +a
    /srv/venv/bin/python scripts/anet_teams.py --unfetched --no-logos --no-core \
        --sports xc,tf --rate 1.0 --write

Two nav calls per team at 1/s. `--sports xc` halves it but silently misses
TF-only teams. `--rate 0.5` halves it again — a decision about anet, not a
setting.

### Phase 1 — build `team_identity`

    /srv/venv/bin/python racecast/build_team_identity.py --dry-run
    /srv/venv/bin/python racecast/build_team_identity.py --write

One row per team id: school, state, city, level, athlete and row counts.
`anet_state` first; the row-modal state only where anet states nothing.
`anet_team.state` is deliberately NOT a fallback — it is itself the
modal-state inference this replaces (hence Georgetown's `anet_state DC` vs
`state ID`).

Its report prints how many teams the rows name that still have no metadata.
**If that is not ~0, Phase 0 did not finish.**

### Phase 2 — the tfrrs bridge

    /srv/venv/bin/python scripts/link_tfrrs_to_anet.py --since 2015
    /srv/venv/bin/python scripts/link_tfrrs_to_anet.py --since 2015 --write

Already existed and already does the right thing: athlete votes,
MIN_ATHLETES=5, MIN_SHARE=0.60, and a college-level gate so a high school can
never be voted onto a college tfrrs string. Read the new ROW coverage lines
first. If coverage is high, the remainder is a footnote and Phase 4 can
proceed; if it is low, widening the gate to high-school tfrrs strings is the
next design question and should be decided on that number, not assumed.

### Phase 3 — crests keyed on team id  (NOT WRITTEN)

The point of doing identity first. One team, one crest. This deletes
`_family`, `sharedShas`, `sharedAlready`, `_isRosterish` and
`--unfile-misplaced` — every heuristic added on 2026-09-18 — because "a
district placeholder" becomes "one image on several team ids", which is a
count rather than a guess about names.

### Phase 4 — the site reads team id  (NOT WRITTEN)

Pages, labels, links. `/school/<name>?state=` → team-keyed, old URLs
redirecting. Name+state stays as the secondary key for rows with no team.

### Phase 5 — clean-slate crest rescrape by team id  (NOT WRITTEN)

## Lesson worth keeping

Three fixes shipped today on theories that the data disproved afterwards,
and two browser checks that were answered by a week-old cache. The rule that
would have prevented all five: **read the row before changing the code**, and
compare digests server-side rather than looking at images through a browser.
`scripts/diag_crest_read.py` exists for exactly this and should be the first
thing run on any crest complaint.
