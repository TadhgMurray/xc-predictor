# PART 1 — WHAT IS RUNNING

Started 2026-09-20 in tmux, both chains:

```
tmux ls                       # the sessions are pipeline-4 and overnightscrape-5
tmux attach -t pipeline-4
```

`tmux new -t NAME` groups a new session with an existing one, which is why the
names came out suffixed; `-s` is the flag that names a fresh session. Harmless.

```
tail -f engine/data/overnight/compute/00-progress.log     # the compute chain
tail -f engine/data/overnight/scrape/00-progress.log      # crests + failed meets
```

**compute chain** (`scripts/overnight_fit_pool_solve.sh`): curve → ability
deciles → school levels → team identity → team pool → `run_pipeline.sh --from 5
--skip 08b_ladder` (backfill → **pack rebuild, where the geometry lands** →
`08_golive` the bracket solve → `08a_holdout` → tilt → rankings → unit builders)
→ `diag_joint_vs_bracket.py`.

**scrape chain** (`scripts/overnight_logos.sh`): anet crests
(`--logos-only --write --replace`, the long one) → the open-web crest scraper →
the 143 failed meets, which wait on the compute chain's `RESULTS-BUSY` lock.

**To stop either:** attach and press **Ctrl-C**. The chain traps
`EXIT INT TERM` and removes its lock. `tmux kill-session` sends SIGHUP, which
the trap does **not** catch — then
`rm -f engine/data/overnight/compute/RESULTS-BUSY` by hand or the next compute
chain waits forever.

# PART 2 — WHAT TO READ WHEN IT LANDS

In this order. Each one can invalidate the ones below it.

**1. The geometry census, in `08_golive`'s output.**

```
[engine] track geometry: N of M course keys carry a track_length; K are flat outdoor 400s
```

`K` is the anchor. If it is small, or the line says *unavailable*, the pin
silently became the old outdoor-mean gauge and everything below is moot.
`python engine/track_geometry.py` prints the full census with the biggest
qualifying keys.

**2. The pin took.**

```
[bracket] gauge=flat400: <n> flat outdoor 400m cells are the reference, <m> with votes and held at 0.0 exactly
```

The failure mode is loud: `⚠ NO reference cell has a vote`.

**3. Indoor, and its gates.**

```
[bracket] indoor: centre asserted at +0.30%, <n> indoor cells with votes, median ...
        <k> outside the -0.3%..+2.0% gates -- PUBLISHED ANYWAY
```

A large share outside is evidence **the centre is wrong**, not that the ovals
are. That is the only feedback an asserted number gets.

**4. §4, the race-day noise — the new measurement.**

```
[bracket] race-day noise at the PINNED reference cells: X% over <n> races
        TF:out's own multi-race estimate is Y% -- the pinned cells say ±Z% against it
```

`Z` is the selection bias, measured for the first time: the course prior is
fitted on the 17,333 XC courses with 2+ races and applied to the 14,147 with
one. Small `Z` vindicates the confounded estimator; large `Z` is the size of a
real problem.

**5. `engine/data/overnight/compute/joint_vs_bracket.log` — option (a).**

Both estimators re-gauged onto the reference class. The number that matters is
**the shift the JOINT column needed** to reach that reference: that is "every
course outside California went negative" as a single figure. Then the negative
share per estimator, which is the owner's own test.

**6. The owner's test, on the published table.** Non-California courses must
stop being uniformly negative. One query on `course_difficulties`, before
anything is trusted.

# PART 3 — WHAT CHANGED IN THE ENGINE

## Changes that alter what a solve publishes

1. **The distance curve.** `fit_distance_exponent`: `MERGE_SPORTS` defaults
   True, degree by location count, and the level prior replaced by a
   **curvature** penalty (the old one arched a genuinely flat curve — truth
   1.120 came out 1.134 mid, 1.076 at the ends). Changes `normalized_time`
   corpus-wide through the backfill.
2. **Indoor's centre, and this one is on by default.**
   `fit(indoor_centre=INDOOR_CENTRE)` — every bracket fit now shrinks thin
   indoor cells toward **+0.3%** instead of toward the indoor cells' own
   measured mean. A target, not a clamp: a well-raced oval still reports what
   its races say. The owner's call, on the fit's −1.68%: *"yeah the fit is
   wrong"*.
3. **`run_joint` stopped double-gauging.** Two bugs, both found by looking for
   why `XCP_INDOOR_LEVEL=0.003` never landed:
   - `bracketDifficulties` **never passed a gauge** to the engine, so it always
     took its default and no flag could reach it;
   - it then **re-centred every cell on the outdoor mean after** the engine had
     already set its zero. Nearly harmless for outdoor; for indoor it is why
     an asserted +0.3% published as −1.68%.
4. **`team_pool`'s verdict reaches the solve** (`resolvePool(team_pro=...)`),
   `loadProTeams` queries `kind` rather than a column that does not exist, and
   `anet_teams` can finally import `loadTeamLevels` — so crests stop all
   landing under **no level**, which is the key Amherst College and Amherst
   Regional High share.

## Behind a flag — live for the next solve, inert before it

- **`gauge=flat400`** (§2): the flat-outdoor-400 reference class, each cell
  held at **0.0 exactly**, not their mean at 0.0. `deploy/solve_env.sh` sets
  `XCP_GAUGE=flat400`.
- **`XCP_BRACKET_INDOOR_CENTRE=0.003`**, the same number `XCP_INDOOR_LEVEL`
  asserts to the joint solve, now reaching the engine that publishes.
- **`XCP_DAY_NOISE=fitted`** (§4): measures the pinned cells' race-day spread
  and prints it beside the historic estimate, changing nothing.
  `--day-noise reference` uses it, and is to be *scored* first.

## Built and deliberately off

- The **athlete prior** (`PRIOR_ATHLETE = 0.0`) and its shrinkage target
  (`PRIOR_TARGET = "median"`). See PART 4 — the sweep says leave both alone.

## New data, no behaviour of its own

- `track_length` / `track_type` / `track_indoor` per course key on the pack
  (`speed_ratings.attachCourseGeometry`, `speed_ratings_db.loadCourseGeometry`),
  and `engine/track_geometry.py`'s one predicate. The modal claim per
  (location, surface) weighted by meets — a length is a fact about a facility,
  not a quantity to average — with the five curated override venues fetched
  meet by meet through `applyVenueOverride` itself, because their corrections
  sit on date boundaries a `GROUP BY` would straddle.
- `track_type` is stored as `U32`, **not** object: `loadCols` reads with
  `allow_pickle=False`, so an object array saves and then silently fails to
  load.

# PART 4 — SETTLED, AND NOT TO BE RE-LITIGATED

**Shrinkage: leave it off.** Measured on one sample, identical coverage:

```
off      0.041938
mean     0.041900     -0.09%
median   0.041909     -0.07%
```

The owner asked for *more* shrinkage. `fit` already estimates k per pool from
the data, so that is the most the corpus supports, and it buys 0.09%. The
athletes really are that different.

**Pool composition does not measurably contaminate difficulty.**
`mean − median = −0.000009`. My hypothesis — that `pro` holding 218,231
athletes, 11,980 of its 12,310 teams caught by the athlete bar rather than by a
professional, was dragging levels — is refuted. *Caveat kept honest:* the
holdout scores predicted times, and a shift in a cell's difficulty partly
cancels against the athlete levels in that cell, so this is not proof about the
published numbers. Moot while the prior is off.

**The `<15` rule is catching what it says it catches.** 163 of 11,980 team ids
(1.4%) would clear 15 on their distinct roster across all their ids; 11,448 of
11,712 schools hold exactly one. My roster-splitting theory is refuted — they
are genuinely tiny: homeschool co-ops, micro Christian academies, Alaskan
village schools.

**Indoor: the fit is wrong, the assertion stands.** Owner's decision.
`XCP_INDOOR_LEVEL=0.003` is a pin, and −1.68% was a symptom of the double
gauge, not a measurement to respect.

**The taper / championship-importance theory is dead** (2026-09-19, owner):
Foot Locker and NXN would both show it and do not. `XCP_IMPORTANCE=none`.

**Five Foot Locker theories are refuted** (island, taper, thin-cell shrinkage,
stratum/window, no-Georgetown-team). Do not propose a sixth without a
measurement attached.

# PART 6 — KNOWN HAZARDS

**The suite runs now, and it is not green.** `bash scripts/run_tests.sh` —
first full pass: 1,408 passed, 39 failed, 6 collection errors, 8 script-style
failures. `tests/conftest.py` keeps the twenty script-style files out of
collection (**detected by AST**, not listed, so the twenty-first cannot break it
silently) and the runner executes them separately.

**Most of the remaining reds are not drift — they are cross-test pollution.**
Ten-plus test files install a **fake `database` module into `sys.modules` at
import time and never remove it**, so whichever runs first poisons every later
import of `database` in the same process. `test_course_scale` fails in a group
and passes alone for exactly this reason. Not fixed: the fakes go in at module
import, so the honest fix is per-file teardown across all of them, and a central
hack would break the tests that rely on their fake. **Do this before trusting
any suite count.**

**An unrunnable suite is an absent suite.** `test_lint_getconn.py` has caught
`conn = getConn()` since 2026-09-10 and did not catch it on 2026-09-19, because
nobody could run the suite. Four wrong-CLI invocations in the chain scripts
"succeeded" the same way. `tests/test_chain_invocations.py` now checks every
`step` line: the target exists, every long flag is one its argparse declares (a
script with **no** argparse must be passed none — that is how
`launcher.py --retry-failed` did nothing), and a script that demands a mode flag
gets one.

**A prior that cannot be exercised at fixture scale needs a fixture at its
scale.** `_fitAthletePrior` needed 200 multi-row athlete-seasons before it ran
at all, so its arithmetic had never once executed in a test and shipped with
`cnt[multi]` — a per-group array indexed by a per-row mask. It crashed on the
owner's first real sweep. `test_athlete_prior` now builds 250 and asserts
`"1 of 1 pools fitted"`, because `"0 of 1"` would pass a weaker check.

**42 team ids have no metadata and never will.** They come back from anet as
`"team": null` — they are not anet teams. Something upstream writes them onto
result rows; that is the fix, not another scrape. `anet_teams`' abort hint now
reads the body and says which failure it is.

**GitGuardian.** The incident from 2026-09-19 needs marking as a false positive
in the dashboard by the owner; `.gitguardian.yaml` pins the ignores to exact
strings so a real secret in the same files still reports. Real credentials live
in `/etc/xc-predictor.env` (server, not in the repo) and
`scripts/config_local.py` (gitignored, untracked).

**31 older test files still set `XCP_DB_PASSWORD` inline.** `tests/_env.py`
