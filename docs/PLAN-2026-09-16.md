## 0. DECIDED 2026-09-16

**Nuke a race on a pool record — but not naively.** Owner: *"nuke anything,
except make it the world record for diff anchors bcs for example college anchors
at 8k. So make it not naive and then nuke on pool records."*

`normalized_time` is **not** a 5k for everybody. `targetFor(pool)` is the
anchor, and the anchors are measured, not chosen:

| pool | anchor |
|---|---|
| elem_* | 2414 |
| ms_* | 3200 |
| hs_* | 5000 |
| college_f | 6000 |
| **college_m** | **8000** |

So the record to beat is the world record **at that pool's anchor distance**,
times that pool's floor factor — never "the 5k WR" against a number that is an
8k equivalent. Getting that wrong would condemn every college men's race in the
corpus, because an 8k equivalent is always slower than a 5k record.

    floor(pool) = recordPace(targetFor(pool), sex) * targetFor(pool)/1000
                  * PACE_FLOOR_SLACK * poolFactor(pool)

⚠ This overrules ISSUES K's row-only rule, knowingly. K removed race-level
nuking on pool records because the rows that beat a young pool's record are, by
construction, the ones the POOLING got wrong — and deleting the race deletes the
evidence that would repool the athlete. The owner has priced that against the
boards and chosen the nuke. Two things make it survivable and both must ship
with it:

1. **The pooling fix lands first.** Every rule in §3 exists to stop the
   mis-pooling that produces these rows. Nuke before pooling is fixed and the
   nuke eats real races.
2. **The condemnation is a table, never a column.** `impossible_race` rebuilds
   `impossible_result` from scratch on every run and nothing else persists a
   verdict, so a nuke is always undoable by one rerun. Keep it that way.

**No anet team → pro, and an unlinked school NAME → pro.** Owner: *"for w/o team
id yes, but also nuke if it's not linked to an anet row (the actual school name
not the specific athlete or race so it's not too overbearing)."*

* an **anet** row with `team_id` 0 or NULL → pro (`no_team`, already shipped).
* a school **name** that no anet team is linked to → pro. Name-level, so one
  odd row cannot move an athlete.
* ⚠ **`link_tfrrs_to_anet` has to run first.** A tfrrs row has no anet team id
  by construction, so "unlinked name" without the link table means *every
  tfrrs-only college goes pro*. The link is what makes this rule safe, and its
  dry run has not been read yet.

## 1. School scrape — ✅ can start now

```bash
python scripts/scrape_school_logos.py --write --fix-multi   # repair first
python scripts/anet_teams.py --queue-only --unfetched       # size it
python scripts/anet_teams.py --write --unfetched            # then resume
```

`--fix-multi` before `--unfetched`, so the repair is not competing with a run
that is still filing crests.

**Then, in this order:** `build_school_identity.py` (the contested list is built
from the team ids the scrape just landed) → `link_tfrrs_to_anet.py --show 60`
(read the dry run before writing) → restart the app (`_LABELS` and `_CRESTS` are
per-process caches; nothing shows until the workers recycle).

### What "looks good" should mean — measure it, don't eyeball it
* `--queue-only` first: the queue size decides whether `--min-rows` is needed.
* The closing line's three hold-backs: `kept`, `placeholder`, `stateless`. A big
  `stateless` means pairs with no state to file a crest under, which is a
  clustering problem, not a crest problem.
* A coverage census before and after: how many `(school, state)` pairs have a
  servable crest, and what share of `ranking_results` rows they cover. "Some
  logos are wrong" is unfalsifiable; "crest coverage went from 38% to 61% of
  rows and 210 pairs hold two institutions" is not.
* Spot-check the known collisions by hand: Oregon, Williams, MIT, Tufts,
  Amherst — label, crest and link on a **race** page, a **school** page and a
  **board**, since those are three different resolvers.

### Sections / divisions redo
Owner: *"now they are generally right but some are fucked up."*
`anet_teams.py` already stores anet's own unit hierarchy per team and sport in
`anet_division` (`scripts/anet_units.py --report` learns what its ids mean from
the units we already infer). Today's units come from **championship
attendance**, which is an inference; anet's structure is a statement. Prefer
anet where it exists, keep the inference as the fallback, and print the
disagreements — a disagreement list is the fix list.

## 2. Rescrape anet + tfrrs — ⚠ one change first

**BLOCKER: `meets_tf` has no venue-name column.** Its columns are `div_id,
meet_id, meet_name, event_short, event_id, distance_meters, gps_lat, gps_long,
state, is_indoor`. There is nowhere to put a facility name, which is why a TF
venue key ends up being an id. This is a column plus the loader that fills it,
and it must land **before** the rescrape or the rescrape happens twice.

While that column is being added, take the rest of what a TF meet knows and we
throw away: the facility/venue name, the meet's own URL (for auditing a bad
parse later), and whether the venue is banked — `is_indoor` alone cannot tell a
flat 300 m track from a banked 200 m one, and geometry reads both.

### tfrrs column shifts
The guard is a per-meet **shape assertion**, not a spot check: every parsed row
must have a place that is an integer or blank, a time that parses to seconds in
a plausible band, and a name that does not itself parse as a time. A meet
failing more than a small share of its rows is rejected whole and counted — one
census line per run naming the rejects. A shifted column fails all three tests
at once, which is why the assertion catches it and a spot check does not.

### Anything else
* **Idempotency**: the rescrape must be safe to re-run over rows it already has
  (upsert on the natural key), or a half-finished run leaves duplicates that
  look like real double-entries.
* **Capture the scrape date per row** so "when did this get worse" is answerable.

## 4. Engine — the four ideas

* **Remove track difficulty (at least for now).** Indoor comes out ~4% *easy*,
  which is backwards — an indoor 200 m with tight turns is harder, not easier,
  and the sign says the cell is absorbing something else (season timing, who
  races indoors). ISSUES A. Removing it is honest: no correction beats a
  correction with the wrong sign.
* **The XC race duplicated into a TF race (AMO).** Same day, same clock, either
  sport → one race. Match on `(person_id, date, time_seconds)` and collapse.
  ⚠ Decide which copy survives *by rule*, not by which was scraped first: keep
  the one whose sport matches the meet's own sport, and when that cannot be
  told, keep XC in the autumn and TF in the spring. Print the collapses.
* **5k normalization = track 5k.** This is the anchor question, and it wants
  ISSUES J done first: `hs_m|XC` currently runs at a local exponent of 1.12
  where the same athletes' `hs_m|TF` runs 1.075 and the world records imply
  1.06. Anchoring the XC 5k to the track 5k while the XC curve is bent puts the
  bend into every conversion instead of removing it. **Refit, then anchor.**
* **Then the ladder, not a guess**: `run_joint.py --holdout` before and after
  each of these, so "better" is a number. An engine change that improves the
  boards and worsens the holdout is a change to argue about, not to ship.

## 5. Extraction → train

* **Label a school as `(name, state, id)`**, and let the id be the **linked**
  anet team id so a tfrrs row and an anet row for one school carry one label.
  A string label makes Oregon (IL) and Oregon (OR) one embedding, which is the
  same collision the site had.
* ⚠ **The label has to be stable across re-extractions** or the embedding
  learned last run means something else this run. The id gives that; a modal
  state does not, so put the id first in the key and treat `(name, state)` as
  display.
* **ISSUES G is fixed but unbanked**: the extraction could not see 25.1% of
  rated college XC (6,505 of 25,894 rows, tfrrs-sourced). The fix is committed
  and the re-extraction is what collects it. Smoke-test `_XC_SQL` over a few
  chunks first — it has never been executed, because `corrections` is
  server-only.
* **Cull `corrections` and back it up first.** It is 165 MB and the import is
  most of a pipeline step. Back up the table and the file, cull what the
  override audit now rejects, and measure the import time before and after so
  the cull is justified by a number.
* **The σ gate** — owner: *"more than 5-15 sigma from their season's median →
  do not rate or rank."* Use a **robust** spread (MAD, or the season's IQR), not
  a standard deviation: one 10σ outlier inflates the SD enough to hide itself.
  Require a minimum number of races in the season before the gate can fire, and
  drop the row from the **solve as well as the boards** — a row that absurd
  should not be evidence about a course either. Census line per run.
