## 0. THE FIVE THINGS THAT WILL BITE YOU

Read these before touching anything. Each one has already cost a day.

1. **`engine/corrections.py` is not in git.** 165 MB against GitHub's
   100 MB hard limit. It travels by `scp`, and **after every `git pull`
   on a server you must copy it again**. A missing corrections.py does
   not crash anything -- it silently un-applies every correction.
2. **No normalized time ⇒ no rating.** The backfill NULLs
   `normalized_time` for skipped rows but historically carried
   `speed_rating` across untouched. Anything that nukes a row must NULL
   both. `scripts/run_checklist.py` fails if this is ever violated.
3. **Wheelchair is a property of the ATHLETE, not the race.** One
   labelled chair race withholds that person's whole career, both
   sports, both feeds. See §7.1 -- *this is currently reported as not
   working.*
4. **Distance corrections are downward-only.** A correction may only
   shorten a scraped distance. The checklist enforces it.
5. **Postgres majors must match or the server must be newer.**
   `pg_restore` refuses a dump from a newer `pg_dump`, and `pg_dump`
   refuses to dump from a newer server -- there is no meeting in the
   middle. Workstation was 18, box shipped with 16, so the box was
   upgraded (§3.3).

## 1. WHAT THIS IS

Racecast rates every US high-school and college cross-country and track
performance on one comparable scale, so a 5K in Michigan in 2014 and a
3200 m in California in 2025 can be put side by side.

The chain, end to end:

```
scrapers  ->  results / results_tf        raw marks, two feeds (anet, tfrrs)
   |
backfill  ->  normalized_time             every mark on a 5K-equivalent scale
   |            (distance curve, course difficulty, era, weather, sport gap)
   |
solve     ->  speed_rating                the engine's own rating per row
   |
boards    ->  ranking_results             what the site ranks
   |            athlete_season, team_season
   |
site      ->  racecast/ (Flask)           athlete, school, race, meet, course,
                                          rankings, predictions pages
```

**The ruler** is `engine/data/*.pkl` -- `distance_spline`,
`geometry_spline`, `era_curve`, `weather_correction_XC/TF`,
`school_levels`. `normalized_time` means nothing without them. They are
now **in git** (they were silently ignored for months by a bare
`data/` rule; fixed 2026-08-27, commit `06d8996`).

### 2.3 The checklist (step 17)

`scripts/run_checklist.py` -- read-only, exit 0 = all pass. Enforces the
owner's four conditions plus two invariants:

- rows are not overturned willy-nilly (no drop block past the 2000 rail)
- corrections apply and only ever shorten distance; corrected and
  dropped divisions never rank

- **no athlete who ever raced a wheelchair division carries a rating**

### 3.3 The Postgres version trap

`deploy/server_pg_major.sh <major>` adds the PGDG repo, installs the
major, drops the old cluster (**refusing if it holds more than an empty
database**), puts the new one on 5432, re-applies the 128 GB tuning and
recreates the DB. `server_restore.sh` now reads the dump's own
`Dumped by pg_dump version` header and refuses early with the fix.

### 3.4 Shipping from a workstation

```powershell
.\deploy\ship_when_ready.ps1                 # dump, then model
.\deploy\ship_when_ready.ps1 -Only dump
.\deploy\ship_when_ready.ps1 -Only model
```

Waits on **evidence of completion** -- the `pg_dump` process exiting, and
`model.pt` being newer than the run started -- never on a guess. Probes
the server's Postgres version over ssh. Refuses to ship a model unless
**all four** artifacts exist: `model.pt`, `target_stats.pkl`,
`encoders.pkl`, `venue_vocab.pkl` (the site loads all four; shipping the
weights alone gives a site that 500s on every prediction).

### 3.5 What ships in the dump

`scripts/cull_db.py` buckets every table:

- **PRODUCTION** -- ships. ~154 GB live, 13.03 GB compressed.
- **DROPPABLE** -- staging/backup junk, ~142 GB, excluded and safe to drop.
- **REGENERABLE** -- a pipeline step rebuilds them, ~90 GB, excluded from
  the dump but kept locally.
- **REVIEW** -- anything unlisted. **Not excluded**, so it ships by
  accident. Add new tables to `_PRODUCTION` explicitly.

⚠ A table rebuilt by a pipeline step is *not* automatically REGENERABLE.
The server **restores and serves** long before it runs a pipeline, so
anything the pages read at load must be PRODUCTION. `school_unit` and
`school_identity` are both in that category.

## 6. SUBSYSTEMS WORTH KNOWING

### 6.1 The sport gap (XC vs TF), and its closed loop

`recenterSport` moves the mean per-athlete sport offset `bbar` out of
beta and into the difficulties. Measuring `bbar` naively is confounded:
inside an academic year the sport contrast is perfectly collinear with
time, so "track is easier" and "the athlete grew up over the winter"
look identical.

`scripts/measure_sport_gap.py` removes the trend by construction with a
**sandwich estimator** -- TF-XC-TF and XC-TF-XC, interpolating the
athlete's own level across the middle race by date. The mean of the two
directions is D with curvature cancelled exactly; half their difference
*is* the curvature.

The loop: 08 applies a bbar and records it; 10c measures D on the
resulting ratings and writes `measured = applied + D` for tomorrow.
**D converging toward 0 across nights is the loop working.**

Latest: applied **-0.04976**, measured D **+0.00473**, next
**-0.04503**. D was +0.01203 before the stale-rating scrub, so most of
the remaining error was polluted rows rather than a wrong gap.

⚠ **One global bbar cannot fix the per-pool spread.** hs_m sits at
+0.0072 and hs_f at -0.0144 -- opposite signs. The tool rules out the
distance curve as the cause (D/span is not constant). Per-pool
recentering is the real fix and is an engine change. See §8.2.

### 6.2 School units (new)

Schools do not publish their league or section anywhere the feeds carry.
What the feeds *do* carry is **attendance**: every school runs its own
late-season championship series -- the LCD meet -- and the meet's name
names the unit. So the unit is inferred from who shows up, season by
season.

- `scripts/check_school_units.py` -- the census and the parser. One
  implementation, two consumers.
- `racecast/build_school_units.py` -- step 10d, writes `school_unit`.
- `engine/school_unit_overrides.py` -- hand corrections. **Prefer an
  alias** (fixes every school at once, survives a rescrape) over a
  per-school verdict (fixes one, needs revisiting when they move).
- `racecast/school_units.py` -- the reader every page uses.

Rules the owner set, encoded:

- **Most recent season is the end-all.** `asof` records which.
- **A division is not its own unit** at high school: you are in NCS
  Division 1 and, separately, CA Division 4. Order runs widest-first
  down each branch: state, state div, section, section div.
- **College is the opposite**: a division IS its own unit and it leads --
  national, division, region, conference.
- Conflicts are **recorded, not resolved**: richest unit wins the column,
  `conflict` is set, and the page shows an amber `?`.

`tests/test_school_units.py` pins both hierarchies so an edit to one
cannot reshape the other.

Diagnostics: `--conflicts` (what the `!` flags disagree about, with the
meet names), `--unparsed` (parser misses), `--school NAME` (provenance).

### 6.3 Rowguard (steps 15/16)

diag → triage → apply. Finds anomalous rows by comparing an athlete's
race against the ones **directly around it in time**, within the same
level bucket -- never across pools, because pool membership changes the
rating scale and a cross-pool comparison would condemn a row for being
in a different pool. 2000-row rail per night; anything past it diverts
to `.OVER-CAP` for a human.

**Issue #23**: an earlier version mass-dropped 1.4M rows because the
echo query keyed on `speed_rating > 0` instead of `normalized_time > 0`
-- rows whose rating had been withheld looked like they had no alibi.
`scripts/amnesty_result_drops.py` is the drop-blind retrial that undid it.

## 7. OPEN BUGS

### 7.1 ⚠ WHEELCHAIR FIX REPORTED NOT WORKING -- and "do corrections actually apply?"

**Reported 2026-08-27 by the owner, after the fix shipped.** Two
questions, and they may be the same question.

The fix (commits `592cd33`, `6c2dcfe`) does three things:
1. `scripts/scrub_stale.py` -- one-time scrub of the existing DB.
2. `engine/fill_ratings.py` -- scrubs stale ratings every run.
3. `backfill_normalize.py` -- a skipped row now **lands as NULL** on the
   update path too, and the person-level propagation withholds every
   race of anyone who ever raced a chair division.

**Diagnose in this order. Do not assume the code is wrong before
checking it ran.**

```sql
-- 1. Did the scrub ever run? These must be 0.
SELECT count(*) FROM results     WHERE normalized_time IS NULL AND speed_rating IS NOT NULL;
SELECT count(*) FROM results_tf  WHERE normalized_time IS NULL AND speed_rating IS NOT NULL;

-- 2. Are labelled chair rows still rated?
SELECT count(*) FROM results r JOIN meets m
  ON m.div_id=r.div_id AND m.meet_id=r.meet_id AND m.source=r.source
 WHERE m.division ~* 'wheelchair|seated|ambulator' AND r.speed_rating IS NOT NULL;
SELECT count(*) FROM results_tf WHERE event_short ~* 'wheelchair|seated|ambulator'
   AND speed_rating IS NOT NULL;

-- 3. Do corrections reach the DB at all?
SELECT count(*) FROM dist_override;          -- ~10,491 expected
SELECT count(*) FROM dist_drop;
-- any override that RAISES a scraped distance is a bug (must be 0):
SELECT count(*) FROM dist_override d JOIN meets m
  ON m.meet_id=d.meet_id AND m.div_id=d.div_id
 WHERE m.distance IS NOT NULL AND d.distance > m.distance + 1;

-- 4. Do corrected/dropped divisions still rank? (must be 0)
SELECT count(*) FROM ranking_results rr JOIN results r ON r.result_id=rr.result_id
  JOIN dist_override d ON d.meet_id=r.meet_id AND d.div_id=r.div_id WHERE rr.sport='XC';
```

Then, in order:

- `python scripts\run_checklist.py` -- it tests all of the above and
  names which one failed.
- If §1 is non-zero, **the scrub never ran on this database.** Run
  `python scripts\scrub_stale.py` (report), then `--write`, then
  `.\run_pipeline.ps1 -From 10`.
- If §1 is zero but §2 is not, the scrub ran and something **re-wrote**
  ratings afterwards -- suspect a pipeline step ordering problem
  (09b fill after the scrub without the invariant, or a partial
  `-From` run that skipped 09b's scrub).
- If §3 shows `dist_override` empty or small, `engine/dump_overrides.py`
  has not run since corrections changed -- that alone makes every
  correction invisible to the site while the corrections file looks fine.
- **Suspect `corrections.py` first on the server.** It is not in git. If
  a `git pull` reverted or removed it, corrections silently vanish and
  everything above reads as "the fix didn't work". Check
  `ls -la /srv/xc-predictor/engine/corrections.py` -- it should be ~165 MB.

**Recommended permanent fix:** `scripts/verify_corrections.py`, a single
read-only command that answers "did corrections actually apply" with
counts and a verdict, so this question never needs a human to reason
through it again. Not yet written.

## 8. IMPROVEMENT PLANS

### 8.1 Website

**Committed to, mocked, not built:**

- **Virtual unit meet** ("compare all NCS teams on this course"). Gap 1
  is done -- `league`, `section`, `section_div`, `district`, `county`,
  `class`, `conference`, `region`, `division` all filter the athlete and
  team boards, and compose with the existing `course` filter. Gap 2 is
  the prediction side: `/api/predict/team` caps at **20 teams**, a
  hand-picking guard with no computational basis (`predictTeam` makes
  one batched `_predictTimes` call; cost is linear in athletes). A
  section is ~150 schools ≈ 1,050 athlete predictions. Raise the cap,
  measure the wall-clock, and design the output.
  **Owner decision outstanding:** should a unit board show those teams
  with their *national* placings (current behaviour -- a subject filter),
  or scored *only against each other* (a real section meet)? The second
  is probably what the virtual meet wants.
- **Unit filters have no UI.** They work as URL params only. Needs a
  mock before coding.
- **Wheelchair explanation banner.** A chair athlete's whole career is a
  column of dashes with no explanation, which reads as the site being
  broken or as erasure. `raceExtras` raises a withheld banner only for
  `dist_drop`. Wording proposed: *"Ratings aren't shown for wheelchair
  events: the speed model is calibrated on running times and the two
  aren't comparable."* Longer-term the honest answer is a **wheelchair
  pool** rated on its own scale, with its own boards.

**Backlog:** #8 About rewrite; TF meet cleanup (Arcadia 2/3); #1 twin
sweep; #6 alias map; #20 Fadesere detector; #4 apparent temperature;
#3 TF distance depth; state-offset check; forum.

### 8.2 Pipeline / engine

1. **Move corrections out of a Python file into tables.** The single
   highest-value change. `dist_override` and `dist_drop` are already
   tables; the drops belong beside them. Kills the 165 MB file, the
   42 MB `.pyc`, the out-of-band copy, the import cost in every process,
   and makes corrections ride the dump like everything else.
2. **Per-pool sport recentering** (§6.1/§7.3).
3. **`verify_corrections.py`** (§7.1) -- one command that answers
   "did corrections apply" definitively.
4. **Stream the feature extractor.** `model/feature_extraction.py`
   accumulates every training example in a Python list before chunking;
   on a 4.3M-athlete corpus that is a memory risk. Flush per chunk.
5. **Weekly rescrape on the server.** 16 cores, and scrape state
   (`meet_queue`, `tf_recovery_queue`, `tf_scraped_events`,
   `meets_tf_meta`) all ship in the dump, so progress survives the move.
   Needs a cron and a runbook.
6. **Backups.** The box has no backup addon and is now the only copy of
   both the database and `corrections.py`. At minimum a weekly
   `pg_dump` to object storage.
7. **Rotate the DB password** everywhere the legacy one may linger, and
   delete the fallback in `scripts/config.py`.
8. **course_boards full build** (`--all`) outside the pipeline once
   there is a machine with hours to spare.
